Архитектура инструмента «Project-to-PProg»
Инструмент будет представлять собой настольное приложение (Python + веб-интерфейс Flask или оконный на PyQt), состоящее из следующих основных модулей:

Модуль 1: Парсер проектной документации
Вход: PDF-файл(ы) проектной документации.
Задача: Извлечь все структурированные данные, соответствующие будущим объектам конфигурации PProg.

На основе предоставленного проекта (62/21-ИОС5.1) парсер будет извлекать следующие блоки, сопоставляя их с сущностями PProg:

Данные из проекта	Извлекаемая информация	Целевая сущность в PProg
Раздел 3.1, 3.2, Спецификация	Типы устройств (С2000М, С2000-КДЛ-2И, С2000-СП2 и др.)	Device Types (стр. 35). В проекте используются стандартные типы, поэтому можно создать соответствующие им дескрипторы.
Структурная схема, Таблица токов (стр. 12-13)	Перечень устройств с сетевыми адресами: ARK127, ARK1, ARK2, SC39-40, ARK3, ARK4...	Devices (стр. 47). Каждое устройство добавляется в список с адресом, типом и версией.
Таблица принадлежности ИП к ЗКПС (стр. 23), Планы расположения	Разделы (Partitions) и входящие в них Зоны. 15 зон (ЗКПС) с конкретными адресными извещателями (BTH...).	Partitions (стр. 55), Zones. Извещатели DIP-34A, IPR 513-3A, S2000-IPDL на планах — это зоны, включаемые в разделы.
Раздел 3.2, Структурная схема	Реле / Исполнительные устройства (С2000-СП2) и алгоритмы централизованного управления. SC39-40 -> Табло "Выход", SC41-42 -> Маяк-12-3М...	Relays (стр. 69). Для каждого выхода С2000-СП2 назначается раздел(ы) и программа управления (например, "Лампа", "Сирена").
Раздел 3.1	Алгоритмы принятия решения о пожаре: A для ИПР, B для ДИП и ИПДЛ.	Настройка параметров зон в разделах или Management Scenarios (стр. 125) для сложной логики.
Раздел 6, Таблицы расчетов	Источники питания и резерв. Данные для понимания системы, но не для прямого программирования логики.	Не является отдельной сущностью в логике PProg, но важно для документации.
Техническая реализация парсера:

PyMuPDF для извлечения текста и таблиц из PDF.

Регулярные выражения для поиска ключевых паттернов: ARK\d+, SC\d+-\d+, BTH\d+, "С2000М", "ДИП-34А", "ИПР 513", а также для парсинга таблиц токопотребления и принадлежности.

Словари для маппинга русских названий устройств на внутренние типы PProg: {"С2000М исп.02": "S2000M console", "С2000-КДЛ-2И исп.01": "S2000-KDL-2I controller", ...}.

Модуль 2: База знаний по оборудованию «Болид»
Содержит JSON/YAML-справочник, связывающий модели устройств из проектов (например, «ДИП-34А-03») с их внутренними идентификаторами, параметрами и типами в PProg. Это позволит парсеру автоматически подставлять правильные значения.

json
{
  "ДИП-34А-03": {
    "pprog_type": "Addressable Smoke Detector",
    "parent_device_template": "S2000-KDL Template", 
    "zone_type": "Smoke Analog Addressable",
    "algorithm": "B"
  },
  "ИПР 513-ЗАМ исп.01": {
    "pprog_type": "Addressable Manual Call Point",
    "parent_device_template": "S2000-KDL Template",
    "zone_type": "Manual Call Points",
    "algorithm": "A"
  }
}
Модуль 3: Интерактивный редактор конфигурации (GUI)
Это центральный элемент для ручного дополнения данных. После парсинга пользователь видит многостраничный интерфейс, визуально похожий на PProg (как показано в руководстве), но с уже заполненными полями.

Компоненты редактора:

Дерево объектов: Слева — список разделов, устройств, реле (как в PProg). Пользователь может добавлять, удалять, редактировать.

Инспектор свойств: При выборе объекта справа отображаются его параметры для ручной правки.

Страницы для ручного ввода:

Devices: Окно для указания недостающих адресов, версий, описаний. Кнопка «Найти устройства онлайн» (по аналогии с PProg, стр. 49) для верификации.

Partitions: Окно для перетаскивания зон из списка устройств в разделы (визуально, как на стр. 56-57 руководства). Позволяет вручную скорректировать состав разделов, если парсер ошибся. Указание типа зоны (Auxiliary, Manual Call Points и т.д.).

Relays: Окно для назначения реле разделам и выбора программы управления (Switch On, Blink, ASPT), задержки и времени активации (стр. 69-76).

Management Scenarios: Конструктор для сложных сценариев (стр. 125-145), который позволяет создать, например, сценарий «Пожар»:

Условие: Partition 1 (Fire) == TRUE

Действие 1: Relay (SC41-42) -> Program "Siren", Delay: 0s, Time: 300s

Действие 2: Relay (SC39-40) -> Program "Lamp", Delay: 0s, Time: infinite

Валидатор: В реальном времени подсвечивает ошибки: дубликаты адресов, пустые обязательные поля, несовместимые типы устройств и программ реле.

Модуль 4: Генератор выходного файла
Задача: Преобразовать внутреннее представление конфигурации из редактора в формат, пригодный для импорта в PProg.

Основная цель:
Сгенерировать текстовый .txt файл, формат которого идентичен тому, что создает сама PProg при команде File → Save. Для этого необходимо:

Получить от НВП «Болид» документацию на текстовый формат.

Если документация недоступна — выполнить обратную разработку: создать несколько простых конфигураций в PProg, сохранить их как .txt и проанализировать структуру. Обычно это ключ=значение, сгруппированные по объектам.

Альтернативная цель (если формат закрыт):
Сгенерировать промежуточный структурированный файл (JSON/XML) и подробный отчет в Excel, где каждая вкладка соответствует странице PProg. Пользователь сможет использовать этот отчет для ручного программирования или написать свой конвертер на его основе.

Модуль 5: Экспорт данных в PProg (ручной)
Учитывая рекомендации руководства (стр. 26-34), инструмент подготовит рабочее место:

Сохранит сгенерированный .txt конфигурационный файл на диск.

Предоставит пошаговую инструкцию прямо в интерфейсе:

Подключите ПК к консоли С2000М (порт RS-232/USB).

Включите питание консоли и переведите ее в режим «PROGRAMMING».

Запустите PProg, на странице Devices нажмите Start Searching.

В меню File → Open откройте сгенерированный .txt файл.

В меню S2000 → Write Configuration запишите конфигурацию в память консоли.

Пример работы инструмента
Загрузка PDF: Пользователь загружает файл 62/21-ИОС5.1.ТЧ.pdf.

Автоматический парсинг: Инструмент извлекает:

Устройства: С2000М (адрес 127), С2000-КДЛ-2И (1), 5хС2000-СП2 (39-46), С2000-БКИ (2), RS-200T (3).

Извещатели: 38 адресных дымовых (BTH...), распределенных по 15 разделам согласно таблице.

Оповещатели: Привязаны к выходам СП2. SC39-40-> Табло, SC41-42-> Сирены.

Ручное уточнение в редакторе:

Пользователь перетаскивает зоны оповещателей с планов в соответствующие разделы (если нужно).

На странице Relays настраивает для SC41-42 программу 2 (Siren), время активации 300 сек.

На странице Management Scenarios создает сценарий «Эвакуация» с условием Раздел 1...15 (Пожар) и действием Запустить Сценарий звукового оповещения.

Генерация: Нажатием кнопки создается файл Мазутонасосная_Щеткина_4.txt.

Импорт: Пользователь открывает его в PProg и записывает в консоль С2000М.

Технологический стек
Язык: Python 3.10+

GUI: PySide6 (PyQt6) для настольного кроссплатформенного приложения, имитирующего внешний вид PProg.

Парсинг PDF: PyMuPDF + pandas для работы с таблицами.

Данные: Внутренняя модель данных на основе dataclasses или pydantic для строгой типизации.

Генерация отчета: openpyxl для Excel, lxml для XML.
